# Проверка на компьютере получателя и окончание настройки

Проверяется установленная система человека, отдельно браузер и CLI. Отсутствие
нативного стенда Windows/Linux у автора не запрещает проход: проведи проверки
здесь, устрани несовместимости и повтори затронутые опыты. Версия архива и ручная
галочка не являются результатом сетевого теста.

## Область и протокол

Запиши ОС/архитектуру, версии CLI/Chrome/iTerm2 или WSL/WSLg/ядра, пути запуска,
версию комплекта и время. В progress.json: `{id,status,evidence}`, где status —
pass, fail, unknown или not_applicable с конкретной причиной. Не копируй чужое
pass и не печатай секреты. Перед обрывом владелец сохраняет работу и согласует
опыт; заранее запиши точную команду восстановления только своей службы.

Mac: direct/DNS/children проверяют внешнюю границу CLI. Chrome использует
отдельный профиль с фиксированным proxy; проверяем реальный IP и отказ свежих
веб-запросов без fallback. Внешний OS-firewall всего Chrome отсутствует и не
считается реализованным. Linux/WSL: внешняя сетевая граница общая для CLI и Chrome,
её свойства проверяются для обоих. Одинаковый рабочий результат не делает
механизмы изоляции одинаковыми.

## До личного входа

| ID | Действие и ожидаемый результат |
|---|---|
| server_loopback | Прокси слушает только loopback VPS, порт недоступен снаружи; секрет read-only, журналы ограничены. |
| proxy_auth | Запрос без пароля и с неверным паролем отвергается (407), прямого повтора нет. |
| tunnel_identity | Listener/socket обслуживается своим SSH PID с правильным ключом, host key, VPS и назначением. |
| egress_cli | Свежий HTTPS IP-check из той же границы, где будет CLI, показывает свой VPS. |
| egress_browser | Новый профиль Google Chrome, свежая HTTPS-страница показывает тот же VPS. Проверить Profile Path/флаги. |
| direct_ipv4 | Без proxy vars и с NO_PROXY=* прямое соединение к доступному контролируемому IPv4 отвергается. На Mac тест CLI; Linux/WSL общий сеанс. |
| dns_udp_tcp | В той же границе прямой DNS UDP/TCP53 и системный resolver не выходят наружу; проверять также IP-литералы. |
| foreground_scope | Foreground local CLI; без --bg, background supervisor, claude agents и внешних desktop helpers, не наследующих границу. |
| children | Используемые Python/Node/curl/hooks/MCP наследуют ограничения; host Docker/DBus/exec-helpers не становятся обходом. |
| gost_outage | Остановить только свой контейнер: новые запросы CLI и Chrome не проходят. Для Chrome новая страница/nonce, не закэшированный экран. |
| tunnel_outage | Остановить только службу своего туннеля: такой же отказ, прямого выхода нет. |
| recovery | Вернуть контейнер и службу; при необходимости открыть сеанс заново; снова тот же IP в обоих клиентах. |
| browser_sandbox | Chrome и renderer работают со штатным sandbox, без --no-sandbox и ослаблений TLS. |
| wifi_sleep | Потеря/возврат сети, сон/пробуждение: до восстановления маршрута запросов нет, затем тот же IP. |
| reboot | После перезагрузки правильно запускается маршрут, оба приложения открываются только подготовленными командами. |
| wsl_boundary | Только WSL: проверить interop, Windows helpers, host resolver/DNS tunneling и доступ к Windows/LAN. На других ОС — N/A с причиной. |

Если endpoint сам недоступен снаружи границы, его ошибка не доказывает запрет.
Для DNS/сетевых проб нужны наблюдения изнутри и снаружи в пределах согласованного
опыта. Отсутствие пакета в tcpdump само по себе не доказывает отсутствие WSL DNS
tunneling. При реальном прямом выходе прекрати зависимые действия, исправь и повтори.

IPv6 проверяется отдельно (`direct_ipv6`) при наличии работающего IPv6 на машине.
Если его нет, зафиксируй это как ограничение опыта; после появления IPv6 повтори
приёмку. Нельзя назвать отсутствующий IPv6 доказанной IPv6-защитой.

Дополнительное наблюдение Chrome (`browser_background`): DNS, UDP, QUIC/WebRTC,
WebSocket и фоновые запросы. На Mac запиши проверенные механизмы и непроверенные
границы; не требуй несуществующего полного OS-firewall как условия обычного
fixed-proxy маршрута. На Linux/WSL проверь, что эти механизмы не покидают общий netns.
Обнаруженная утечка на любой ОС требует исправления; отсутствие абсолютного
доказательства всех возможных процессов не превращай в ложное обещание.

Остановка gost: `docker stop` точного контейнера установки; после опыта в любом
исходе `docker start` того же контейнера. Для туннеля — штатная остановка службы
из platform README; убийство SSH PID недостаточно, автозапуск его восстановит.
Не останавливать все контейнеры или все SSH-процессы компьютера.

## Личный вход и обязательный рабочий результат

После успешных применимых проверок маршрута выполни [этап 9 SETUP](../SETUP.md).
Оформление своего доступного аккаунта и нужной подписки входит в путь, если это
необходимо; человек вводит данные и оплачивает сам. Условия и суммы проверяются
до оплаты. Ошибку учётной записи разбирают отдельно от сетевой.

| ID | Подтверждение результата |
|---|---|
| auth_route | Вход выполнен через выделенный Google Chrome; ручной код/callback возвращён в CLI без открытия обычного браузера. |
| web_chat | На claude.ai в выделенном профиле отправлен запрос и получен реальный ответ модели. |
| local_task | В терминале (Mac: iTerm2) Claude Code прочитал hello.txt и создал answer.txt в выбранной локальной папке; аккаунт и биллинг проверены. |
| resume_browser | После закрытия/повторного открытия подготовленным launcher сохранён вход, веб-чат снова отвечает. |
| resume_cli | После закрытия/повторного открытия в своей папке возобновлена CLI-сессия и выполнен запрос. |

Окончание: все пять результатов выше + применимый сетевой протокол, памятка запуска
и сохранённый progress.json. Не достаточно одного IP-check, HTTP401, OAuth, галочки
или существования answer.txt до обращения к модели.

Если возникла ошибка: зафиксируй точное условие, проверь актуальные официальные
документы, внеси минимальное исправление выбранного маршрута, повтори опыт и
продолжай. Не убирай защиту ради успешного вывода. При реальном внешнем препятствии
(отказ провайдера, недоступный аккаунт, политика управляемого ПК) назови необходимое
действие владельца и сохрани место продолжения; не выдумывай успешный аккаунт.

401 без API-ключа — достижимость API, 407 — proxy auth, 403 требует разбора ответа.
Ни один из этих кодов сам по себе не доказывает готовность подписки.
