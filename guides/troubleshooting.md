# Если что-то не работает

Начни с времени сбоя, приложения, точного сообщения и последнего изменения. Отсутствие испытаний этой ОС у автора не является ошибкой установки: проверь её здесь, исправляй конкретные несовместимости и продолжай до web-chat и CLI. Если уже есть progress.json от rc1, сохрани его результаты, убери только прежний общий запрет продолжения; реальные незавершённые проверки выполни. Не начинай с очистки аккаунта, покупки другого VPS или переустановки всей системы.

| Симптом | Следующее действие |
|---|---|
| `python3`/`py` не найден | Открой HTML; установи Python по официальной ссылке из SETUP. Не путай отсутствие Python с проблемой прокси. |
| «Файл уже существует» у init/prepare | Сохрани прежний прогресс. Для нового примера выбери новую папку; для продолжения читай существующую. |
| Порт 48921 занят | Определи владельца listener безопасной описью. Не завершай неизвестный процесс и не считай его своим туннелем. |
| SSH host key changed | Не удаляй known_hosts вслепую. Сверь сервер/переустановку и fingerprint через независимую консоль провайдера. |
| SSH не соединяется | Сначала доступность своего VPS/22, ключ/права, затем служба и журналы без env/секретов. Не отключай StrictHostKeyChecking. |
| 407 от прокси | Проверь наличие/формат proxy.auth локально, права и совпадение пары с server secrets; пароль не печатай. |
| 401 от API без ключа | Это ожидаемый результат диагностической пробы, не ошибка подписки. |
| Сессия перенесена в background | Остановить приёмку этого режима: supervisor может миновать wrapper. Вернуться к принятому foreground-запуску; само возвращение не доказывает маршрут, повторить проверки. |
| Красная панель при живом Claude | Посмотри именно результат Claude и время пробы. Другой проверяемый сервис может делать общий индикатор красным. |
| `Waiting for API response` | Сверь время API, туннель и сервер; одиночная долгая проба не устанавливает причину. |
| OAuth ждёт localhost | Используй документированный ручной код в защищённом браузере или исправь точный локальный callback. Не открывай обычный браузер. |
| Chrome падает под sandbox | Не добавляй --no-sandbox. Останови приёмку этого механизма и разбери совместимость на испытательной среде. |
| После обновления CLI исчезла защита | Проверь путь запуска и ссылку claude-native. До восстановления wrapper и повторных тестов не входи напрямую. |
| WSL не запускается/нет WSLg | Прочитай Windows README и версию WSL/Windows. Не заменяй защищённый Linux Chrome обычным Windows Chrome. |
| Интернет компьютера сломался | Откатить только последнее именованное правило/службу комплекта. Не сбрасывать глобальные настройки всех VPN и firewall. |

## Ежедневная проверка

Открой защищённый launcher, проверь свежий статус туннеля и адрес выхода, затем свой проект. После сна дождись восстановления. Сохранённая зелёная отметка страницы не измеряет живую сеть. Закрытие терминала с foreground Chrome может закрыть браузер; SSH-служба работает отдельно.

## Обновление

Запиши версии, сохрани пользовательские данные и точный путь текущего CLI. Поставь обновление официальным способом; проверь, не заменило ли оно ссылку wrapper. Повтори соответствующие сетевые испытания. Не копируй старый протокол как проверку новой версии. Автоматического updater в комплекте нет.

## Точечное отключение

Сначала закрыть только клиенты комплекта. Остановить его службу туннеля по platform README, отключить её автозапуск; убрать только явно установленные файлы из install-manifest. Ключ туннеля при окончательном отказе отозвать на своём VPS. Рабочие проекты и сессии сохранить. Возврат обычной команды Claude снимает этот способ ограничения — объяснить это владельцу до возврата ссылки.

Отмена очистки и отключение туннеля — разные действия. Не восстанавливать старый аккаунт автоматически. Удаление серверных ресурсов/подписки выполняется отдельно с проверкой оплачиваемых объектов; остановка приложения на компьютере не отменяет счета.

## Что передать в поддержку

Версия комплекта, ОС/WSL/Chrome/CLI, этап, время по своему часовому поясу, безопасный текст ошибки и последний успешный шаг. Перед отправкой проверить отчёт на секреты и личные пути. Не прикладывать `.env`, proxy.auth, ключи, cookies, `.credentials.json`, полный settings/config панели, логи входа или историю проектов. Внутренние ограничения сети описать словами; сырые дампы не нужны.

## Как агент доводит несовместимость до решения

Одна наблюдаемая ошибка → её минимальное воспроизведение → актуальная официальная
документация установленной версии → исправление конкретного компонента → повтор
проверки → следующий этап. Перед изменением запиши откат. Не повторяй одну и ту же
неудачную команду бесконечно. При необходимости нового платного инструмента, VM
или другого провайдера сначала объясни изменение условий владельцу. Если нужное
действие доступно только владельцу/поддержке, сохрани конкретный запрос и продолжай
независимые этапы. Рабочий результат проверяется в обоих приложениях после ремонта.
