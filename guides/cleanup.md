# Очистка прежнего входа с сохранением работы

Этап обязателен перед новым входом для участника с прежним заблокированным аккаунтом и сохранившимся локальным состоянием. Это обслуживание локальной установки, не обещание разблокировки. При диагностике уже работающей сети очистку не повторяют.

## Сначала опись и согласие

Codex определяет реальные HOME/USERPROFILE и `CLAUDE_CONFIG_DIR`, не подставляет путь автора. На Windows отдельно проверяет native-установку и каждый используемый WSL-дистрибутив. Политики организации не отключаются.

Показать пользователю таблицу: точный путь/элемент, что это, размер, действие, что останется, как отменить. Закрыть Claude CLI/Desktop и их фоновые помощники; отключить старое расширение Claude в прежнем профиле Chrome. Обычный Chrome целиком не сбрасывать. Убедиться, что процесс не пишет в очищаемый файл.

Составить список сохраняемых рабочих каталогов и хеши обычных файлов; симлинки учитывать как ссылки, не обходить их за пределы выбранной области. Не выводить содержимое истории. Секреты и браузерные профили не добавлять в Git. Полных копий домашней папки, `.claude`, VM и проектов не делать. Точечные JSON и перемещённые данные хранятся приватно, отдельно от раздатки; перенос на том же диске не создаёт вторую многогигабайтную копию.

После согласия на список применять операции последовательно, записывая «исходный путь → новый путь/изменённые поля → проверка». При ошибке остановиться на текущем объекте, не удалять всё для повторной попытки.

## macOS — восстановленный точный рецепт

1. `~/.claude.json`: разобрать JSON в памяти, удалить только верхнеуровневые `machineID`, `userID`, `anonymousId`, `oauthAccount`, если они есть. Остальные поля должны остаться равны исходным значениям. Запись — временный файл с правами 600, проверка JSON, атомарная замена. При невалидном JSON сначала исправление/восстановление, не создание пустого файла поверх.
2. Keychain: исторически использовался сервис `Claude Code-credentials`. Для нестандартного config dir/новой версии имя может отличаться. Проверить соответствие реальной установке, не удалять все элементы со словом Claude. Для обнаружения использовать `security find-generic-password -s 'Claude Code-credentials'`, скрывая stdout/stderr и сохраняя только exit code. Не использовать `-w`/`-g` для вывода значения. После отдельного согласия удалить только выбранную запись через `security delete-generic-password -s 'Claude Code-credentials'`. Код 44 при следующем поиске означает отсутствие этой записи. Это не удаление серверного аккаунта/подписки. Удаление записи Keychain нельзя отменить простым возвратом файла: без отдельного заранее согласованного способа восстановления потребуется новый штатный вход в доступный аккаунт после приёмки сети. Ради «резервной копии» не извлекать и не печатать токен. Это последствие явно показать перед согласием.
3. По согласованной описи точечно переместить из активных мест существующие каталоги ниже. Не создавать новые пустые папки, выдавая их за старые. Не перемещать каталог, если место назначения уже занято.

| От HOME пользователя | Что проверить до перемещения |
|---|---|
| `Library/Application Support/Claude` | Desktop-сессии, MCP-конфиг и VM могут быть ценными. Сначала перечислить категории и сохранить нужное пользователю; весь каталог не считать кэшем. |
| `Library/Caches/com.anthropic.claudefordesktop` | Кэш Desktop. |
| `Library/Preferences/com.anthropic.claudefordesktop.plist` | Настройки Desktop. |
| `Applications/Claude.app` | В эталоне это был пользовательский launcher. Проверить тип объекта; не удалять произвольное приложение по совпадению имени. |
| `.claude/telemetry`, `.claude/cache`, `.claude/chrome` | Только существующие служебные каталоги выбранной установки. |

4. Проверить отсутствие вложенного `.claude/.claude.json`; если он есть, выяснить роль. В эталоне его не было. `chromeExtension.pairedDeviceId` не входит в подтверждённые удалённые поля — не удалять его автоматически по пересказам.
5. CLI-бинарник, `Claude Code URL Handler.app`, `projects`, `skills`, `hooks`, `commands`, `file-history`, плагины, MCP и рабочие папки сохраняются. Сверить их хеши и цели ссылок после операции.
6. Новый браузерный профиль создаётся позже, при настройке маршрута, без импорта старых cookies. Простой профиль в меню Chrome не получает сетевую защиту автоматически.

## Windows и Linux

Официальная документация описывает CLI credentials на Linux/Windows в `.credentials.json` внутри выбранного каталога конфигурации; при заданном `CLAUDE_CONFIG_DIR` учитывать его. На macOS вход обычно находится в Keychain. [Хранение входа](https://code.claude.com/docs/en/authentication#credential-management).

Агент определяет существующий каталог, записывает лишь имя/наличие/права файла и после согласия точечно выводит старый credential-файл из использования. Не выводит токены, не удаляет `settings.json` с MCP и не чистит все Windows Credential Manager записи.

Для Desktop пути меняются между обычной установкой, MSIX/Store, enterprise и версиями. `%APPDATA%\Claude` — кандидат для поиска, не универсальная команда удаления. Определить фактическое место по типу пакета, настройкам приложения и текущей официальной справке. Если найдено несколько профилей, показать их владельцу и выбрать один. В Linux аналогично учитывать XDG_CONFIG_HOME и установленный вариант Desktop. Неизвестный путь означает остановку этого шага.

Старое состояние Windows и новая WSL-среда — разные области. Очистка файла в WSL не очищает вход native Windows. При чистом новом WSL не нужно притворяться, что в нём были старые credentials.

## Настройки необязательного трафика

В исторической конфигурации были `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, `CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL=1` и `skipWebFetchPreflight:true`. Их нельзя считать kill switch.

Первую настройку применять после проверки поддержки текущей версией и объяснения влияния на обновления. Вторую — только если текущая версия её действительно поддерживает. `skipWebFetchPreflight` отключает отдельную проверку WebFetch; в новом комплекте она **не включается автоматически**, так как не требуется для SSH-маршрута. Исторический рецепт сохранён, отличие обозначено. Изменения JSON сливаются с существующим документом, не заменяют весь файл. [Параметры](https://code.claude.com/docs/en/env-vars), [settings](https://code.claude.com/docs/en/settings).

## Проверка и отмена

Проверить: старые выбранные credentials отсутствуют, JSON валиден, сохранённые поддеревья неизменны, прежние программы больше не создают старое состояние. Авторизацию не запускать ради проверки, пока сеть не принята.

Отмена: остановить соответствующие приложения, вернуть только конкретные перемещённые файлы на свободные исходные места. Если уже появились новые данные, сравнить и сохранить их, не накатывать прежнюю папку поверх. Возврат старого входа — отдельное осознанное действие владельца, не автоматическая реакция на сетевой сбой.
