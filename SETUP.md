# Рабочий доступ через Алматы с нуля

Версия **1.0.0**, 6 ноября 2026. Полный комплект для настройки вместе со своим Codex.
Конечный результат: Claude отвечает в отдельном Google Chrome и выполняет
задачи с локальными файлами через Claude Code; на Mac используется iTerm2.
После закрытия оба приложения снова открываются по подготовленному маршруту.

У каждой ОС свои настройки и проверки. macOS опирается на изученную рабочую
схему; Windows/Ubuntu ещё не проходили нативные испытания у автора. Это сведения
о проверке выпуска, а не запрет установки: агент проверяет и исправляет конкретную
машину получателя до результата. Стоп возможен из-за реальной неустранённой ошибки
или необходимого действия владельца, а не из-за отсутствия авторского стенда.

Рабочие файлы находятся на твоём компьютере. Собственный VPS в Алматы передаёт
сетевые запросы. Mac Chrome использует один обязательный proxy без DIRECT;
CLI имеет отдельное ограничение ОС. Linux/WSL используют общую изолированную
сетевую среду CLI и браузера. Приёмка проверяет свойства выбранного маршрута;
полный внешний firewall Mac Chrome комплектом не заявляется.

**Терминал** — окно команд. **VPS/VDS** — арендованный постоянно работающий компьютер. **SSH** — зашифрованное соединение с ним. **Прокси** — посредник сетевых запросов. **Защита от прямого выхода** — отдельное ограничение ОС, которое сохраняется при ошибке прокси. Наличие прокси и наличие такой защиты — разные результаты.

Проекты не переносятся на сервер. Его 1 ГБ памяти не определяет, сколько памяти доступно для твоего монтажа или кода. Веб-чат Claude, Claude Code и Codex — разные приложения. Codex здесь помогает настроить Claude; его сеть автоматически не переводится через Алматы.

## Для агента перед первым действием

Прочитай [локальную инструкцию скилла](skills/almaty-access/SKILL.md) целиком. Она работает вместе с этой папкой; не переносить один SKILL.md в глобальные навыки и не менять общие правила пользователя.

1. Прочитай `compatibility.json`. Уточни режим: новая установка, продолжение, диагностика или обновление. Отсутствие author runtime-проверки не останавливает работу. Объясни область, выполни необходимые проверки здесь и исправляй выявленные несовместимости.
2. Найди `progress.json`, если он уже есть. Проверь версию и реальные файлы. Записанное `pass` — свидетельство прошлого опыта, не вечная гарантия.
3. Не запускай старый Claude для разведки, если безопасный маршрут ещё не готов. Выясни пути установок, версии по метаданным, активные процессы и службы. Не печатай env, cookies, содержимое credential-файлов, `docker inspect` целиком или SSH-ключи.
4. Все команды в этом тексте — задания конкретного этапа, не разрешение исполнить весь документ за один раз. При неизвестном состоянии фиксируй `unknown`, сохраняй следующий шаг и объясняй причину.
5. Используй файлы только выбранной ОС. Остальные нужны как справка. Не запускай команды macOS в PowerShell.

Поддерживаемая область запуска — **foreground local CLI** и процессы, которые действительно наследуют его внешнюю границу. `claude agents`, `--bg`, `/background`, background supervisor и внешние desktop helpers не приняты. Они могут запускать бинарник по фиксированному пути, минуя PATH wrapper. Не включать их и не переносить туда защищённую сессию. [Официальная сетевая документация](https://code.claude.com/docs/en/network-config).

Перед первым применением конфигурации Codex создаёт рядом с техническим журналом `install-manifest.json`: `{"schema":1,"entries":[]}`. Каждое изменение сначала получает запись с `path`, `kind` (file/service/link), `previous_state`, `action`, `rollback`, `applied:false`; после исполнения — `applied:true` и время. В записи не включать содержимое секретов. Существующие файлы не затирать: либо согласованное точечное перемещение с путём возврата, либо остановка. Для служб записывать точное имя, область пользователя и предыдущий статус; для symlink — прежнюю цель. Откат выполняется по реально применённым записям в обратном порядке. Это не полный снимок системы.

## 1. Подготовь Codex и папку

Установи Codex по [официальной инструкции](https://learn.chatgpt.com/docs/codex/cli), войди в свой аккаунт и открой распакованную папку. На Windows приложение и терминал могут работать в Windows или WSL; это нужно различать. [Официальная справка Windows](https://learn.chatgpt.com/docs/app/windows).

Потребуются доступный Codex, интернет, права на установку ПО, свободное место и собственный способ оплаты сервера. Для итогового Claude Code нужен доступ к сервису по условиям твоего аккаунта; оплата Codex не является оплатой Claude.

Отправь агенту первую фразу из `START.txt`. Не загружай весь домашний каталог и секреты в чат.

**Результат:** Codex видит `SETUP.md`, называет ОС и ведёт полный маршрут. На Mac устанавливает [iTerm2](https://iterm2.com/) из официального источника, если его нет. Для Google Chrome использует официальный установщик под реальную архитектуру компьютера; на Linux/WSL проверяет наличие графической среды.

## 2. Опись компьютера

Если Python 3.10+ установлен, Codex выполняет из папки комплекта:

```sh
python3 kit.py doctor
python3 kit.py init --state progress.json
```

В Windows с Python Launcher (только doctor/init/verify): `py -3 kit.py doctor` и `py -3 kit.py init --state progress.json`. Если Python нет, сначала [официальная установка Python](https://www.python.org/downloads/); для чтения HTML Python не нужен.

`doctor` не запускает Claude, не обращается к VPS, не читает секреты и не меняет настройки. Он не подтверждает сеть. `init` отказывается перезаписывать уже существующий журнал.

Дополнительно агент определяет: установленный CLI и Desktop; их каталоги; способ хранения старого входа; старые службы/прокси; занятость порта 48921; VPN; корпоративные ограничения; тип CPU; пути рабочих проектов. Значения секретов не выводятся. Пользователь выбирает папку для первой тестовой задачи.

**Результат:** краткая опись, список сохраняемых данных и ровно один следующий шаг.

## 3. Подготовь старую установку

Если прежний аккаунт был заблокирован и его локальный вход остался, этап очистки обязателен перед новым входом. Если старого состояния нет, зафиксируй это и пропусти удаления. Если установка уже работает и задача — диагностика обрыва, повторную очистку не выполняй.

Прочитай [точную процедуру](guides/cleanup.md). Агент показывает список конкретных путей и полей, объясняет последствия и ждёт согласия на этот список. Очистка касается локального входа и выбранного служебного состояния. История, проекты, MCP и скиллы сохраняются. Изменение файлов не снимает блокировку аккаунта на стороне сервиса.

**Результат:** журнал выполненных операций, сохранность пользовательских файлов и отсутствие выбранного старого входа. Полного удаления `.claude` нет.

## 4. Создай свой сервер

Прочитай [пошаговый серверный раздел](guides/server.md). Поставщик — [Serverspace](https://serverspace.kz/), [кабинет](https://my.serverspace.kz/). Каждый получатель создаёт свой сервер и оплачивает его сам.

Опорная конфигурация: Алматы, Ubuntu 24.04 LTS x64, 1 vCPU, 1 ГБ RAM, 25 ГБ диска, публичный IPv4. Исторический рабочий заказ 1 ноября 2026 стоил 3 398,45 ₸/месяц; сейчас цену нужно проверить в кабинете, включая канал и почасовое начисление. Не создавать второй сервер автоматически, если первый долго готовится.

Агент сначала показывает параметры и итоговую стоимость. Пользователь подтверждает конкретный заказ. Данные карты, CVV и документы вводятся только в интерфейсе поставщика. Смена IP не заменяет правила аккаунта и оплаты.

**Результат:** один свой VPS, его IPv4, подтверждённый SSH host key, доступ по своему административному ключу. Никаких реквизитов чужого сервера.

## 5. Подготовь VPS и файлы клиента

По [серверной инструкции](guides/server.md) устанавливаются Docker и закрытый gost. Используй `server/` как шаблоны, сначала прочитав их README. Пароль хранится в отдельном файле; proxy-порт снаружи не открыт; отдельный tunnel-пользователь не имеет обычной оболочки.

Для безопасной подготовки параметров клиента:

```sh
python3 kit.py prepare --server-ip 203.0.113.10 --output prepared
```

`203.0.113.10` — пример, замени его IPv4 своего VPS. Утилита помечает адреса примеров, но никуда не подключается. Она создаёт новую папку `prepared`, `deployment.json`, `ssh_config` и памятку; на macOS также plist. Linux/WSL получает Unix-forward. Не перезаписывает существующую папку; пароль и ключи не создаёт.

Codex адаптирует шаблоны по параметрам, проверяет синтаксис и только затем применяет согласованные изменения. SSH config содержит `StrictHostKeyChecking yes`; неизвестный ключ не принимать вслепую. Данные подключения не включать в пересылаемый архив комплекта.

**Результат:** доказано, что прокси доступен только через SSH и требует пароль; локальные параметры подготовлены отдельно от установленной системы.

## 6. Установи маршрут своей ОС

- [macOS](platforms/macos/README.md): launchd, отдельная обёртка CLI и профиль ограничения, отдельный Chrome, iTerm2 как основной терминал; Agentbelt по желанию.
- [Ubuntu Linux](platforms/linux/README.md): отдельное сетевое пространство всего CLI и браузера, relay к SSH, systemd.
- [Windows 11](platforms/windows/README.md): выделенный WSL2 Ubuntu, Linux-механизм изоляции, проверка interop/DNS, браузер через WSLg.

Запрещён тихий переход на обычный CLI, обычный браузер или `DIRECT`, если механизм защиты не работает. Туннель может восстанавливаться автоматически; приложение до этого остаётся без доступа.

**Результат:** готов именованный запуск выбранного маршрута. При сбое агент уточняет причину, исправляет и повторяет проверку; готовые независимые этапы не отменяются.

## 7. Подготовь отдельный браузер

Используй свой пустой каталог профиля, не импортируй cookies старого входа. Один фиксированный прокси, без direct fallback. Штатный sandbox браузера сохраняется. Не добавляй `--no-sandbox`, не отключай проверку TLS.

На Mac воспроизводится отдельный профиль с единственным proxy: подтверждают IP и отказ свежих запросов при остановке proxy/туннеля. Это не внешний firewall всех компонентов Chrome. Дополнительные наблюдения DNS/IPv6/WebRTC записываются отдельно; обнаруженный прямой выход требует исправления до входа. Само отсутствие отдельного OS-firewall не является запретом предусмотренного Mac-маршрута.

Для WSLg/Linux браузер и CLI должны находиться в той же защищённой среде. Локальный OAuth callback требует точного разрешённого локального пути либо документированного ручного ввода кода. Не открывай ссылку в Windows Chrome через `powershell.exe` ради обхода ограничения.

## 8. Проверь до входа

Пройди [протокол приёмки](guides/verification.md). Сначала проверки без аккаунта и без API-ключей. Перед обрывом человек закрывает незавершённые запросы и согласует испытание. Успешный `curl` и ответ 401 подтверждают отдельные звенья, а не всю установку.

**Результат:** отдельный протокол CLI и браузера на конкретной ОС/версии; после каждого сбоя восстановление и повторная проверка. Пока обязательный пункт `unknown` или `fail`, к входу не переходить.

## 9. Войди и получи результат в обоих приложениях

После обязательных сетевых проверок открой [Claude](https://claude.ai/) в новом
Google Chrome этого комплекта. На Mac — launcher `chrome-almaty.command --claude`.
Владелец входит в свой доступный аккаунт либо проходит обычную регистрацию,
если она нужна. При прежней блокировке вопросы аккаунта решаются с сервисом;
очистка локальных файлов не является разблокировкой.

Проверь доступный тариф и актуальные [условия Claude](https://claude.com/pricing).
Для веб-чата и Claude Code нужны подходящие права в аккаунте; бесплатный веб-вход
сам по себе не подтверждает доступ к CLI. Если требуется подписка, агент объясняет
выбранный вариант и сумму, владелец оформляет и оплачивает её сам в интерфейсе
сервиса. Codex и VPS оплачиваются отдельно. Не заказывать второй тариф или API
billing автоматически.

**Веб-результат:** создай новый чат, отправь короткий пробный запрос и дождись
реального ответа. Запиши `web_chat: pass` с временем и наблюдением без содержимого
личной переписки. Один OAuth callback, IP-check или HTTP401 не заменяет этот шаг.

**CLI-результат:** на Mac открой iTerm2, перейди в свою тестовую папку и запусти
`claude-almaty`; в Ubuntu/WSL используй подготовленный сеанс по platform README.
Ссылку авторизации открой в том же выделенном Chrome. Если браузер не открылся,
нажми `c`, перенеси URL вручную; если показан код — введи непосредственно в
терминал, не в чат Codex. На Mac используется ручной flow, поскольку прямой
localhost callback через proxy не разрешён. [Официальный вход](https://code.claude.com/docs/en/authentication).

После `Login successful` проверь `/status`, выбранный аккаунт и способ оплаты,
отсутствие неожиданного API-ключа (только наличие, не значение). Создай `hello.txt`
в выбранной папке и попроси Claude прочитать его и записать `answer.txt` рядом.
Проверь реальный ответ модели и локальное расположение файла, запиши `local_task`.

Закрой оба приложения, снова открой их подготовленными командами, продолжи
веб-чат и CLI-сессию. Отдельные результаты — `resume_browser` и `resume_cli`.
Настройка закончена после всех четырёх результатов и сетевого протокола.

## 10. Завтра, обновления и сбои

Запускай защищённый launcher, проверяй маршрут и открывай свою папку проекта. VPS работает независимо от вкладки терминала; клиентский туннель зависит от ОС и её автозапуска. Chrome launcher работает в открытой вкладке терминала — не закрывай её раньше браузера.

Новый чат Codex: «Прочитай SETUP.md и мой progress.json. Проверь фактическое состояние и продолжи со следующего шага. Очистку не повторяй без новой причины».

Обновление CLI/Chrome/ОС: запиши версии, проверь путь wrapper и повтори соответствующие испытания. Не заменяй ссылку защищённого запуска обычным бинарником. Систему с неисправной защитой не запускай упрощённым способом.

[Помощь при сбоях и точечный откат](guides/troubleshooting.md). Остановка VPS может не прекращать оплату диска/IP: перед окончательным отказом сверяй ресурсы и правила провайдера. Не удаляй сервер, пока он ещё нужен и владелец не подтвердил конкретный объект.

## Состав и целостность

Исходники и ссылки: [SOURCES.md](SOURCES.md). Проверить файлы ZIP после распаковки:

```sh
python3 kit.py verify --manifest MANIFEST.sha256
```

`MANIFEST.sha256` добавляет сборщик: он есть в итоговом ZIP, но не в папке исходников `package` разработчика.

SHA256 выявляет случайную порчу перечисленных файлов. Он не является цифровой подписью автора и не доказывает безопасность сети. Не передавай папки `prepared`, собственный `progress.json`, browser profile и ключи другим людям.

Подготовка `prepare` для Windows выполняется **внутри выбранного Ubuntu WSL2**, с Linux HOME. В native Windows команда откажет до записи. macOS получает TCP-forward и plist; Linux/WSL получает Unix-forward `proxy.sock` и параметры, без plist. Это подготовка файлов, не запуск защиты.
