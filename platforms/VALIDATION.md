# Проверки комплекта и проверки установленного маршрута

Версия **1.0.0**, 6 ноября2026. Выпуск — законченная раздатка для настройки вместе с Codex. Он не означает, что runtime уже проверен на каждом компьютере. Неизвестные native проверки выполняются на машине получателя; их отсутствие у автора не запрещает установку.

## Сборочная проверка

- Шаблоны shell/XML/YAML/INI, подготовительные утилиты и упаковка проверяются офлайн; результаты финального выпуска записаны в его отчёте.
- Linux `session_launcher.py --plan` работает без запуска bwrap/SSH/Chrome; обычный вход больше не требует `--experimental`. Устаревший флаг сохранён.
- Офлайн-тесты Linux engine проверяют mount/argv, ограничения SSH, identity/state, namespaces/WSL interop, отсутствие direct fallback. Добавлена проверка настоящего временного Unix socket: ссылка Wayland разрешается в один socket, socket0777 допускается при защищённом родительском каталоге; обычный файл и каталог с чужой записью отвергаются. Это тест локальных файлов, не WSLg runtime.
- `Start-Almaty.ps1` вызывает реальный Linux engine через указанную WSL2. Старый experimental wrapper перенаправляет в него. PowerShell parser/runtime на сборочном Mac не выполнены: штатный parser запускает Codex на Windows перед первым применением.
- Исторические статические проверки rc1 не переносятся как доказательства сетевой защиты. Тестов действующего VPS/аккаунта/браузера автора при сборке этой версии не выполняли.

## На компьютере получателя

1. После подстановки путей снова проверить полученные shell/XML/unit/PowerShell файлы, включая пробелы/кириллицу. Linux: `systemd-analyze --user verify`; Windows: штатный PowerShell parser.
2. На собственном VPS: `sshd -t`, effective `sshd -T`, native Compose validation, loopback listener, ограниченные ключи, отказ без/с неверным proxy-паролем, правильный маршрут и обрыв/восстановление.
3. macOS: внешний профиль CLI проверяется отдельно; отдельный Chrome проверяется в заявленной области фиксированного HTTP(S)-proxy и отказа новых запросов при обрыве. Настройки proxy не объявляются полной OS-изоляцией всех браузерных каналов.
4. Ubuntu24.04 x64: рабочие bwrap/user namespaces, TTY/CLI, штатная Chrome sandbox/Wayland, общий relay, callback/ручной код, direct/children tests и обрыв/восстановление. Ошибку чинят на этой машине, сохраняя границу и обычную sandbox.
5. Windows11 x64: дополнительно конкретная WSL2, выключенный interop, DNS/WSLg, запуск PE по абсолютному пути, сохранность чужих distro. Повторить Linux-проверки.
6. После обязательной сети: настоящий ответ Claude в отдельном браузере, локальная задача Claude Code, закрытие и повторное открытие обоих приложений с продолжением истории. На Mac CLI работает в iTerm2; на Linux/WSL — в их локальном терминале.
7. Проверить ежедневный ярлык, sleep/wake/reboot и обновление версий. На Linux/WSL ярлык получает новый PID SSH при каждом запуске, а engine сверяет процесс/socket. Отказ не заменяется прямым запуском.

Успешный синтаксис, IP-check, HTTP401/407 и окно приложения доказывают отдельные этапы. Статус установки получателя завершается его свежими наблюдениями по [протоколу](../guides/verification.md). Обнаруженная несовместимость требует конкретного исправления и повторной проверки, а не ожидания испытаний на оборудовании автора.
